# okit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `humpty.okit` library of OCaml-specialist agent tools that drive a
passive `dune` watch server over RPC and query `ocamlmerlin`, wired into
humpty's agent so every write returns build diagnostics in the same tool
result.

**Architecture:** A hand-rolled csexp layer feeds a sequential
request/response RPC client that owns a spawned
`dune build --passive-watch-mode` server. Merlin is queried one-shot via
`ocamlmerlin single`. Tools follow the existing `Deepseek.Toolbox`
conventions: bounded output, truncation announced, capability-confined file
access. See `docs/superpowers/specs/2026-08-02-okit-design.md` (the spec) and
`docs/superpowers/plans/2026-08-02-dune-rpc-protocol.md` (the wire protocol —
**required reading for Tasks 2–4**).

**Tech Stack:** OCaml ≥ 5.2, Eio ≥ 1.4 (`Buf_read`, `Process`, `Net`,
`Path`), jsont (already a dsml dependency), dune ≥ 3.21 to build. The
workspace being served must run dune ≥ 3.24 (RPC v2), verified at menu
negotiation.

## Global Constraints

- Work on the `tools` branch. One commit per task, one-line imperative
  message, **no trailers, no sign-off, no Co-Authored-By**.
- **No new opam dependencies.** `humpty.okit` may use: `deepseek`,
  `deepseek.dsml`, `eio`, `jsont`, `logs`. Tests may add `eio_main`.
- Before every commit, all three must be clean:
  `dune build` and `dune runtest` and `dune build @fmt` (run
  `dune build @fmt --auto-promote` to apply, then check it is clean).
  ocamlformat is pinned at 0.29.0; do not reformat unrelated files.
- Every new `.ml`/`.mli` starts with the repo's 4-line copyright header —
  copy it verbatim from `lib/tool.mli`, keeping the year 2026.
- Doc comments follow the repo norm: `[foo x y] is …`, naming arguments,
  what a caller must know only. Prose: no em-dashes, no semicolon-joined
  clauses, complete sentences. Blank line before each doc comment.
- Tests are hand-rolled in the style of `test/test_scan_tools.ml`: a
  `failures` counter, `check name cond` printing `ok   - name` or
  `FAIL - name`, and a non-zero exit if any failed. No alcotest.
- A tool or library must not silence a failure. When refusing input, say
  what the right form is.
- `CHANGES.md` gains one or two lines per commit that changes what a user
  sees, grouped by commit (Task 8 writes them all).
- Add an entry line for each new module in `okit/` to no index — dune wraps
  the library as `Okit` automatically; do not create `okit/okit.ml`.

- [ ] **Step 5: Implement `okit/csexp.ml`**

`read` on `Eio.Buf_read`: peek one char. `(` → consume, loop reading until
`)`. Digit → read the decimal length up to `:` (refuse lengths over
16 MiB and non-digits with `Failure`), then `Buf_read.take n`. Anything else
→ `Failure` naming the offending byte. `of_string` wraps a
`Flow.string_source`, catches `Failure` and end-of-input into `Error`, and
checks the buffer is exhausted afterwards (`Buf_read.at_end_of_input`).
`to_string` via `Buffer`. `pp` prints atoms with `%S` when they contain
bytes outside graphic ASCII, bare otherwise, lists in parens.

- [ ] **Step 3: Implement**

A recursive `render ~in_vbox` over the node table in the protocol doc:
`Nop`/`Text`/`Verbatim`/`Char`/`Newline`/`Seq`/`Concat`/`Box`/`Hbox`/
`Hvbox`/`Hovbox`/`Vbox`/`Break`/`Tag`. `Break ((l,n,r),(l',n',r'))` renders

- Produces (Task 4 depends on exactly these):

```ocaml
module Error : sig
  type t = { kind : [ `Invalid_request | `Code_error ]; message : string }
end

module Packet : sig
  type t =
    | Request of { id : Csexp.t; method_ : string; params : Csexp.t }
    | Notification of { method_ : string; params : Csexp.t }
    | Response of { id : Csexp.t; result : (Csexp.t, Error.t) result }

  val to_sexp : t -> Csexp.t
  val of_sexp : Csexp.t -> (t, string) result
end

module Loc : sig
  type t = {
    file : string;  (* absolute *)
    line : int;     (* 1-based *)
    col : int;      (* 0-based *)
    stop_line : int;
    stop_col : int;
  }
end

module Diagnostic : sig
  type promotion = { in_build : string; in_source : string }

  type t = {
    id : int;
    severity : [ `Error | `Warning ] option;
    loc : Loc.t option;
    message : string;  (* rendered text, no location header *)
    promotion : promotion list;
    related : (Loc.t * string) list;
  }

  val of_sexp : Csexp.t -> (t, string) result
  val to_text : t -> string
  (** [to_text d] is [d] as the model sees it: a dune-style
      [File "…", line N, characters C-C:] header when there is a location,
      the message, and one line per promotion pair. *)
end

(* Requests. [id] is the packet id. *)
val initialize : Packet.t          (* packet id (initialize), client id okit *)
val version_menu : Packet.t        (* advertises the menu below *)
val ping : id:Csexp.t -> Packet.t
val build : id:Csexp.t -> targets:string list -> Packet.t
val diagnostics : id:Csexp.t -> Packet.t
val flush : id:Csexp.t -> Packet.t
val promote : id:Csexp.t -> path:string -> Packet.t
val shutdown : Packet.t            (* a notification *)

(* Response payload decoders. *)
val decode_menu : Csexp.t -> ((string * int) list, string) result
val decode_outcome : Csexp.t -> ([ `Success | `Failure ], string) result
val decode_diagnostics : Csexp.t -> (Diagnostic.t list, string) result
val decode_flush : Csexp.t -> (unit, string) result

val required_menu : (string * int) list
(** What a negotiated menu must contain for the client to work: build 2,
    diagnostics 2, flush-file-watcher 1, ping 1, promote 1, shutdown 1. *)
```

The advertised menu (in `version_menu`): `build (2)`, `diagnostics (2)`,
`flush-file-watcher (1)`, `notify/abort (1)`, `notify/log (1)`, `ping (1)`,
`promote (1)`, `shutdown (1)`. Advertising only v2 for `build` and
`diagnostics` means an old server drops the method instead of serving a v1
payload we cannot decode.

- [ ] **Step 3: Implement**

Records encode fields in alphabetical order (build the pair list sorted).
Decoders use `Csexp.field` and are strict about shape but not order. Sum
values are two-element lists. `Packet.of_sexp` discriminates by which of
`id`/`method`/`result` are present, per the protocol doc, and refuses
anything else naming what it found. `Diagnostic.of_sexp` renders `message`
(and each `related` message) through `Pp_text.render`, propagating its
error. `to_text` writes
`File "<file>", line <l>, characters <c>-<c'>:` then the severity word when
present, the message, then `wrote <in_source> (run promote to accept)` per
promotion entry — one line each.

```ocaml
type t

val start :
  sw:Eio.Switch.t ->
  proc:[> [ `Generic | `Unix ] Eio.Process.mgr_ty ] Eio.Resource.t ->
  net:_ Eio.Net.t ->
  clock:_ Eio.Time.clock ->
  root:Eio.Fs.dir_ty Eio.Path.t ->
  (t, string) result
(** [start ~sw ~proc ~net ~clock ~root] serves the dune workspace at [root].
    When no server is running it spawns [dune build --passive-watch-mode]
    there and owns it until [sw] finishes. When a server already holds the
    workspace it connects to that one and leaves it running on [stop]. The
    error says what failed: no dune on PATH, no socket within 10 seconds, or
    a menu without the methods okit needs and the dune version to upgrade
    to. *)

type build = { ok : bool; diagnostics : Wire.Diagnostic.t list }

val build : t -> targets:string list -> (build, string) result
(** [build t ~targets] flushes the file watcher, asks the server to build
    [targets] and returns the outcome with the diagnostics the server then
    holds. Diagnostics for the whole workspace are returned, not only for
    [targets]. *)

val promote : t -> path:string -> (unit, string) result
val stop : t -> unit
```

- [ ] **Step 3: Implement**

Points that matter, in the order they bite:

- Socket path: `Eio.Path.native_exn root ^ "/_build/.rpc/dune"`. If it
  exists at start, connect and set `owns = false`. Otherwise spawn
  `dune build --passive-watch-mode` with `~cwd:root` and `~executable`
  resolved from PATH; then retry `Eio.Net.connect ~sw net (`Unix path)`
  every 0.1 s for up to 10 s (`Eio.Time.sleep clock`).
- The spawned server's stdout and stderr must not reach the terminal, which
  the interface owns. Give both a pipe drained by a fiber into a 4 KiB ring
  kept for error messages. When `start` fails or the server dies, the tail
  of that ring goes into the error string.
- Handshake per the protocol doc: send `Wire.initialize`, read until its
  response, send `Wire.version_menu`, read the menu, check
  `Wire.required_menu` is a subset, else
  `Error "dune at <root> is too old for okit: needs build v2 and
  diagnostics v2 (dune >= 3.24)"`.
- One request at a time: `request t packet` writes the packet
  (`Eio.Buf_write`), then reads packets in a loop. `notify/log` →
  `Logs.debug`. `notify/abort` → `Error` with its message. A `Response`
  with the expected id is the answer. Anything else is an `Error` naming
  the packet. Guard the whole exchange with a `Eio.Mutex`.
- `build` = `flush` request (decode, refuse `not_in_watch_mode`), then
  `build` request with the target list, `Wire.decode_outcome`, then
  `diagnostics` request, `Wire.decode_diagnostics`. Packet ids: a counter
  rendered as `(auto N)`.
- EOF mid-request when `owns`: respawn and reconnect once, then re-issue
  the current request; a second EOF is an error. When not `owns`: error
  saying the workspace's own server went away.
- `stop`: when `owns`, send `Wire.shutdown` and close. Also install
  `Eio.Switch.on_release` in `start` so an abandoned session shuts its
  server down.
